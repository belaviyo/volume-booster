Loop-restart audio mute repro

Reproduces the reported Waterfox/LibreWolf bug without the extension: media looped YouTube-style (ended → seek(0) → play()) goes silent when the element is routed through createMediaElementSource, while direct playback keeps working. All media is same-origin (generated blob or local file) so there are no CORS confounders.

How to run the test
  • Keep the tab visible (background throttling can stall the meter). Start with the short tone.
  • Expected if the bug is present: panel A stays audible across loop restarts; panel B goes silent after a restart (red dot, SILENCE DETECTED in its log); pressing +5 s or 0:00 on panel B restores audio (matches the reporter's workaround); panel C stays audible and its log shows KICK applied — which validates the planned extension fix.
  • If panel B does not mute with the short tone, repeat with the long tone (~11 min, matches the report's duration) and then with a real 10+ minute local file.
  • The native loop attribute mode is a comparison: it takes a different Gecko path and may not trigger the bug.
  • Run once in Chrome/Chromium as a control; no panel should ever mute there.
  • Use Copy report to grab the event timeline + silence episodes for the bug report.
  • This page is a standalone test harness, not part of the extension — delete repro-loop-mute.html before packaging.
